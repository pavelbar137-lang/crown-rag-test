# RAG-сервис по базе знаний

Тестовое задание 3: мини-сервис, который загружает текстовый документ,
превращает его в эмбеддинги, кладёт в векторную базу и по вопросу
пользователя находит релевантный кусок текста и генерирует ответ.

## Алгоритм

1. **Загрузка** (`POST /ingest`) — документ приходит как обычный файл. Текст
   нормализуется (схлопывание пробелов) и режется на перекрывающиеся чанки
   по границам предложений (`app/chunking.py`). Перекрытие в 120 символов
   нужно, чтобы факт на стыке двух чанков не терялся целиком в одном из них.
2. **Эмбеддинги** (`app/embeddings.py`) — каждый чанк превращается в вектор
   фиксированной длины. Основной путь — внешний embeddings-API; в этом
   репозитории он не подключён к платному ключу, поэтому используется
   локальный hashing-trick векторизатор (bag-of-words → фиксированный
   вектор через md5-хэш токена, аналог `HashingVectorizer` из
   scikit-learn), нормализованный по L2. Это осознанный выбор для
   тестового: сервис работает офлайн, воспроизводимо и без секретов, а
   контракт `EmbeddingClient.embed(texts) -> np.ndarray` меняется в одном
   месте, если подключать настоящий embeddings-API.
3. **Векторная база** (`app/store.py`) — `faiss.IndexFlatIP` (скалярное
   произведение по нормализованным векторам = косинусное сходство).
   Точный (не приближённый) индекс — для объёма одного регламента/документа
   этого достаточно, ANN здесь избыточен.
4. **Ответ на вопрос** (`POST /ask`) — вопрос эмбеддится тем же клиентом,
   ищутся `top_k` ближайших чанков, они уходят в LLM с системным промптом
   «отвечай строго по контексту, не знаешь — так и скажи»
   (`app/llm.py`). Если `ANTHROPIC_API_KEY` не задан, сервис не притворяется,
   что сгенерировал ответ, а честно возвращает лучший найденный фрагмент
   с пометкой `[офлайн-режим, без LLM]` — это видно и в ответе API (поле
   `mode`), и в `GET /health`.

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Опционально — реальная генерация ответа моделью Claude:

```bash
export ANTHROPIC_API_KEY=...
```

## Пример

```bash
curl -F "file=@regulation.txt" http://127.0.0.1:8000/ingest
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "сколько дней даётся на возврат оборудования при увольнении"}'
```

## Тесты

```bash
pytest -q
```

Покрыты: разбивка на чанки (включая пустой документ), релевантность поиска
по векторному хранилищу, поведение на пустом индексе.

## Ограничения и что делал бы дальше

- Хранилище живёт в памяти процесса — для продакшена нужна персистентность
  (сохранение индекса на диск или переход на pgvector).
- Hashing-embeddings — рабочая, но не самая точная замена настоящей модели
  эмбеддингов; при наличии платного API её стоит заменить первой.
- Чанкинг по предложениям без учёта структуры документа (заголовки,
  таблицы) — для регламентов с таблицами нужен отдельный парсер.
